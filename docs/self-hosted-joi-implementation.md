# 自建 Joi：施工记录与下一步实测

日期：2026-09-07。当前状态：首版接线与离线验证完成；GPU 画面未验收。

## 已实现

浏览器 → 自建 WebRTC MediaBody → Gateway 媒体 API → 原统一 Runtime/ai-core。
Gateway 原有人格、记忆、角色身份继续使用；视频身体不拥有另一套大脑。

GPU worker 固定接入 SoulX-FlashHead 官方源码版本，实际调用推理函数，没有 Mock 回退。
Pro 每块 17,920 采样/28 帧，Lite 每块 15,360 采样/24 帧；单 GPU 并发 1。
目前 worker 未实现 HTTP 多卡协作，不把上游多卡性能当成本服务实测性能。

媒体服务逐句解码语音，将同一 PCM 交给 GPU 与 WebRTC，共用采样时间戳。
实现了有界队列、全轮 epoch 取消、旧结果丢弃、会话属主、取消后远端清理等待、
断线回收、GPU 未就绪阻止接通、服务端密钥与 Studio 同源白名单。

## 本机入口

- 页面：`http://127.0.0.1:8899/joi?body=selfhost`
- MediaBody：`127.0.0.1:8902`，主服务启动器可选管理，Python 3.12 独立依赖。
- Worker：默认经本地 `127.0.0.1:8092` 转发到 GPU 主机。
- `scripts/selfhost-up.sh --status` 使用服务端令牌读取完整状态，不输出令牌。

`live-up.sh status` 中 media-body 的 ready **只表示本地媒体进程存活**。
GPU 的真实加载与会话可用状态以页面或 `/health` 为准；脑接口健康是配置检查，
并非实际 LLM/TTS/GPU 全链路验证。全链路通过必须来自真实会话记录。

## GPU 接入所需

已选择现有 Windows RTX 5080 作为首测主机，主服务准备从当前 Mac 迁移到 MacBook。
尚未接通 Windows SSH 或执行目标 GPU 推理；先测试 Lite，再决定是否需要其他 GPU。
换机、记忆备份和 WSL2 接线见 [MacBook + Windows 5080 指南](macbook-windows-5080.md)。
不在开发 Mac 安装 CUDA，尚未租用付费 GPU，也未下载大模型权重。

需要一张原创或有授权的成年角色正面近景参考图。准备角色图的内置图像生成请求
遇到网络错误，当前没有把其他照片、电影剧照或静态 CSS 效果替代成已完成的视频。
GPU 端按 `docs/self-hosted-gpu-worker.md` 配置 `AVATAR_SOURCE_IMAGE`。

GPU 启动步骤、固定源码和权重目录见上述文档。模型下载后保留权重版本、镜像 digest
和依赖清单。使用 HTTPS，或将远端 worker 转发到 Mac 的 8092，令牌两端一致。
确认 worker `/health` 的 ready:true 后再开启页面会话。

可使用媒体包 probe 对真实链路发送一轮文字并保存 WebRTC 接收录制与计时；
它会实际使用现有 LLM/TTS 与 GPU，结束时回收会话。详见该包 probe 的 --help。

## 当前证据与诚实边界

Gateway 媒体 API、鉴权、身份与回执回归已通过；GPU worker 的离线协议与取消测试通过。
MediaBody 用真正的本地 RTC peers 验证了音频/视频编码传输、同一时钟、错误帧拒绝、
取消 epoch 和新轮接续；输入是测试专用色块与波形，不是 GPU 真人样片。
浏览器验证了健康检查、未就绪禁用按钮、点击后仅请求麦克风、权限失败不建会话。

这些验证不能证明比 Tavus 更自然。尚未通过：真人 GPU 画面、中文声线与牙齿/眼睛稳定、
跨句视觉连续性、真实麦克风抢话、客户端缓冲清空、自然倾听与 10 分钟连续会话。

当前静止时保持最后一帧；未实现自然听众动作。表情/眼神/手势语义控制也没有实现。
每句等待完整 TTS 音频，模型还需要一个块的缓冲；不是端到端 token 级流式。

首轮 5080 GPU 验收先跑 Lite，测显存与速度；资源允许时再做 Pro 同素材/同音频对照。
随后测试连续说话→打断音画→保留开头接续。
以实际 P50/P95 首声首画、音画偏差、打断停声停嘴时间与人物稳定度决定保留/替换模型，
不能把健康绿灯、单卡吞吐、单张好看的图片或上述测试数量当作体验达标。

## 真实接线检查中发现的问题

第一次真实 Gateway 媒体轮次没有收到台词。Runtime trace 证明模型确实调用成功，
但对用户问话照用了静默示例；将静默示例限定到自主事件，用户轮明确要求回应实际原话。
另发现媒体 event_id 带冒号且过长，被 Replanner 重新生成 correlation，导致台词无法
匹配等待中的轮次。修复应使用满足现有协议的稳定短关联 ID，并区分空回复与真实超时。
重启后的真实复测已通过：本次约 3,256 ms 收到 decision、4,721 ms 收到 MP3、
4,723 ms 收到 done。模型回复「我准备好了！」，音频 20,897 bytes，运行时真实模型
调用计数从 2 增至 3（本轮一次），fallback_count 保持 0，会话已关闭。
这只是单样本大脑/TTS接线时间，不是 GPU 首画或浏览器首播时间，也不是 P50/P95。
证据保存在 outputs/selfhost-diagnostic/brain-probe.json；失败前记录单独保留。

另将正常打断/未知播放的 interrupted 计数与 failed 分开持久化，避免多次插话让
反思认为「speak_line 总做不好」。旧混合计数与历史反思未迁移或删除。

当前相关检查：MediaBody+录制 probe 36 项、Worker 22 项、认知/人格 43 项、
Gateway 真实 WS 路由等针对性回归 39 项、自建前端 19 项与代理 35 项通过；
以上包含隔离假输入，只将真实大脑/TTS复测单独作为实际模型证据。
