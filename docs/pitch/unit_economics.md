# 单位经济模型（可编辑草稿）

> 所有标 **[假设]** 的数字都是按公开定价或行业常识估的占位值，请用实际报价替换。
> 目的是给投资人看"算过账"，以及找出成本结构里真正要优化的那一两项。

### A2. 持续成本（每台每月，按"活跃用户日均 20 轮对话，每轮 1 句 ≈ 40 字"）

| 项目 | 单价 | 月用量 | 月成本（元） |
|---|---|---|---|
| ASR（DashScope 流式） | ¥0.00035/秒 **[假设]** | 20 轮×5 秒×30 天 = 3000 秒 | 1.05 |
| LLM（DeepSeek-chat）输入 | ¥1/百万 token **[假设]** | 每轮含系统提示+记忆约 3k token ×600 轮 = 1.8M | 1.8 |
| LLM 输出 | ¥2/百万 token **[假设]** | 每轮 150 token ×600 = 0.09M | 0.18 |
| 记忆抽取 LLM（每轮一次小调用） | 同上 | ≈ 0.6M 输入 | 0.6 |
| TTS（Fish Audio 克隆音色） | ¥0.1/千字 **[假设]** | 40 字×600 = 24k 字 | 2.4 |
| 嵌入模型 / 向量库 | 自托管 | — | ≈ 0 |
| 服务器（Postgres/Redis/gateway，按 1000 活跃分摊） | ¥800/月 **[假设]** | — | 0.8 |
| **每活跃台每月** | | | **≈ 6.8** |

> 结论：**运行成本每月 < ¥10/台**，TTS 是最大头。切到 Edge/CosyVoice 可降到 ≈ ¥4。
> 非活跃设备成本 ≈ 0（只有服务器分摊）。

### A3. 定价与毛利（两种模式）

| 模式 | 定价 | 单台首年毛利（元） | 说明 |
|---|---|---|---|
| **一次性买断** | 售价 299 **[假设]**，含 1 年服务 | 299 − 100 − 6.8×12×活跃率 60% ≈ **150** | 第二年起收订阅或停服务 |
| **硬件 + 订阅** | 售价 199 + ¥15/月 **[假设]** | 硬件 99 + 订阅 (15−6.8)×12×60% ≈ **158** | 现金流更好，续订率是关键指标 |
| **B2B2C（卖给玩具厂）** | 模组 + 灵魂授权：¥40/台 + ¥5/活跃台/月 **[假设]** | 40 − 模组成本 25 + (5−4.5 可控成本)×… ≈ **15 + 持续** | 走量，靠工厂渠道 |

### A4. 敏感性

- 活跃率从 60% → 30%：订阅模式毛利上升（成本下降）但续订率会跟着掉——**留存比成本重要一个量级**
- 对话量翻倍（40 轮/天）：月成本 ≈ ¥13，仍远低于 ¥15 订阅；成本结构对用量不敏感
- LLM 换国产更便宜模型或自托管 7B：LLM 项可再降 50%，但要重跑内容安全与人格一致性测试

## C. 投资人会追问的三个数（拍摄/试点时顺手采）

1. **D7 / D30 留存**（激活后 7/30 天仍有对话的设备比例）
2. **日均对话轮次** 与 **关系阶段分布**（多少人到了"朋友"以上）
3. **订阅续费率**（若试点阶段就收费）

数据来源：`relationship_states`（阶段、`total_interactions`、`last_interaction_at`）、`ai-core /metrics/latency`、gateway 会话日志——试点前把这三张表的导出脚本准备好。
