# 开口延迟：本轮边界与下一步验收

当前可核对的链路是：统一认知先返回完整且通过 BehaviorDecision 校验的决策，然后 Gateway 按句合成，使用该句 emotion；同轮 PAD 在第一段音频之前发给身体。`decision_complete` 帧让 Gateway 不必再等原来的 600 ms 静默窗口。Gateway done 事件记录 `decision_ms`、`first_audio_ms`，已有设备播放记录仍测真正的首帧发送时间。TTS 合成完成不等于用户听见，播放回执保持独立。

本轮没有实现 LLM token 到首句语音的端到端流式，也没有部署或测速本地模型。Tavus 的 OpenAI SSE 兼容接口目前仍在完整决策完成后分块；不能把这个接口称作低延迟流式认知。

## 端到端流式的下一步

单次模型输出需要一个可增量校验的协议：先发决策身份/有限动作意图，再发带情绪的完整句子，最后关闭该决策。动作必须等相应意图通过校验才执行；句子必须在完整收到、经过内容过滤后才开始 TTS。中途断流应撤销剩余动作，明确标记未完成，不能再发另一套无关台词冒充同一次回复。

优先验收以下真实指标，分别报告 P50/P95、样本数与失败率：

- 用户说话结束 → ASR 稳定结果；
- ASR 稳定结果 → 首个可用认知输出/首个完整句子；
- 首句 → 首段音频到设备 → 实际开始播放；
- 用户打断 → 声音停止、嘴部停止，以及下一轮是否续接上下文。

## 本地推理的接入边界

仓库 `packages/ai-core/src/ai_core/services/llm/registry.py` 已提供 `ollama` 和 OpenAI compatible base URL；本地推理应接在这个 provider 层，继续使用同一个 PromptBuilder、记忆、身份和 BehaviorDecision 契约。不要再创建一套本地人格/记忆。这里只确认代码接入点，不代表任何本地模型已安装或达到质量、速度要求。

ASR 当前的 registry 实际只构造 DashScope provider，Gateway 的流式识别也直接使用 DashScope。仅把 `ASR_PROVIDER` 改为 whisper 并不会得到本地识别；需要新 provider、流式分段/中止契约及 Gateway 接入，随后做同一批音频的识别质量和首结果延迟比较。

P0 验收先使用隔离软件身体：同一人格和历史上下文下，连续说话、打断停止声音与嘴部、随后接续话题。云端与本地用同一测试集比较；角色一致性、结构化输出有效率、动作合法率和记忆命中需要同时达标，不能只比较首 token 速度。
