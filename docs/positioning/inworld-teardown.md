# 竞品拆解：Inworld AI（一页）

> 结论先行：Inworld 证明了"角色/人格运行时"有人付钱，也证明了云锁定路线的天花板。
> 我们不和它拼模型路由和云 TTS；我们打它结构上做不了的三件事：**身份可移植、本地部署、实体硬件通路**。

## 他们做什么（2026 现状）

| 模块 | 内容 | 备注 |
|---|---|---|
| Character Engine | 对话+情绪+记忆+手势的 NPC 引擎（起家业务） | 正在被下面的 Runtime 吸收 |
| **Inworld Runtime** | AI 编排平台：统一 API key 路由所有主流模型（OpenAI/Anthropic 兼容，改 base URL 即接入）、REST/WS/WebRTC | 已从"角色公司"转向"基建公司" |
| TTS/STT | 自研 TTS-1（$5/百万字符）/TTS-1-Max（$10），viseme 口型、流式 | 价格激进，是主要营收面 |
| SDK | Unreal AI Runtime（已发布）、Unity Runtime（早期），API-first | 游戏是主战场 |
| Safety / Memory / Knowledge | 平台内置、免费附送 | **免费**说明他们不认为这层可单独收费 |
| 定价 | 纯用量计费，无订阅 | |

融资/体量：多轮大额融资（$500M+ 估值报道），团队百人级。

## 他们结构上做不了 / 不会做的

1. **身份可移植**：角色定义、记忆、关系全部锁在 Inworld 云。没有导出格式，没有"把角色带去别家模型/别家引擎"。这不是疏忽，是商业模式——用量计费依赖锁定。**`.soul` 的存在理由正是反锁定**：口令即授权、跨模型、跨身体，IP 方/用户拥有灵魂本体。
2. **本地/离线部署**：全云架构。车机、玩具、无网环境、数据不出境的 B 端（国内合规刚需）都接不了。我们的 harness 核心零依赖、可跑在本地小模型上。
3. **实体硬件**：无硬件业务。我们有 Protocol 0.2（同一角色驱动网页 VRM/机器人/语音管道三类身体已验证）+ 自有玩具厂（BOM ¥100 的灯塔 OEM）。
4. **国内栈**：模型（DeepSeek/豆包/Kimi/Qwen）、TTS（edge/fish/dashscope）、合规与网络环境的适配，他们没有动机做。
5. **生活模拟深度**：他们的角色是"被动应答的 NPC"；我们的运行时有日程→小时→分钟规划、四级重规划、角色↔角色对话、空间共处与每日反思（Generative Agents 内核）——角色在没人跟它说话时也在"活着"。这是陪伴与游戏 NPC 拉开体验差距的地方。

## 我们不做什么（明确让出）

- **模型路由/网关**：OpenRouter、各云厂商已卷成红海；harness 只做 OpenAI 兼容双车道客户端，不做计费网关。
- **自研 TTS/STT 模型**：接现成供应商（edge/fish/dashscope/Inworld 自己都行——harness 是中立层）。
- **通用 agent 框架**：不与 LangChain/AutoGen 竞争；我们只管"这个 AI 是谁"，不管"这个 AI 会用什么工具"。

## 一句话定位差

> Inworld 卖的是"更便宜更快地跑 AI 角色的云"；SoulForge 卖的是"**AI 角色的身份层**——灵魂归属用户和 IP 方，跨模型、跨身体、跨厂商随身携带"。

## 对打时的证据清单（融资/BD 用）

- `.soul` 现场演示：同一个文件在 ①网页 VRM ②毛绒玩具 ③终端 quickstart 三处醒来，记忆/关系连续
- 灵魂问卷：3 分钟从用户心理画像生成专属人格（他们没有 C 端人格生成入口）
- 一致性 benchmark：接 harness vs 裸 prompt 的 30 天人格一致性对比（benchmarks/consistency.py）
- 本地部署 demo：断网环境 + 本地小模型跑通完整人格循环
