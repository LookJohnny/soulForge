# The `.soul` Format — Specification v2.0

*Status: Draft. Reference implementation: `soulforge_harness.soul.pack` (MIT).*
*一个 `.soul` 文件 = 一个 AI 角色的完整身份，跨模型、跨身体、跨厂商可移植。*

## 1. Design goals 设计目标

1. **Identity, not user data** — a `.soul` carries the character itself (personality,
   voice, embodiment, expression tuning, knowledge). User-specific state (memories of
   a particular user, relationship progress) is deliberately excluded; it belongs to
   the host's per-user store.
2. **Portable** — no field may reference a vendor account, a model provider, or a
   host-absolute path. A `.soul` opened on any conforming runtime yields the same
   character.
3. **Tamper-evident** — every payload file is hashed in a manifest; any modification
   is detected on read.
4. **Passphrase = license** — optional symmetric encryption where distributing the
   passphrase *is* the licensing act (IP holders hand a code to a licensee).
5. **Forward compatible** — readers MUST ignore unknown files and unknown manifest
   keys.

## 2. Container layout 容器结构

```
offset 0:  4D 61 67 69 63 ─ magic bytes  "SOUL2\n"  (53 4F 55 4C 32 0A)
next:      one line of UTF-8 JSON, terminated by 0x0A   ← the *header*
rest:      payload — a ZIP archive, either plaintext or encrypted (§4)
```

### 2.1 Header

The header is readable without any key. Fields:

| key | type | required | meaning |
|---|---|---|---|
| `enc` | `"none"` \| `"pass"` | ✔ | payload encryption mode |
| `salt` | base64 string | when `enc="pass"` | 16-byte PBKDF2 salt |
| `soul_id` | UUID string | ✔ | stable identity of this soul across re-exports |

Readers MUST reject a header longer than 4 KiB.

## 3. Payload ZIP 内容

| path | required | content |
|---|---|---|
| `manifest.json` | ✔ | see §3.1 |
| `character.json` | ✔ | portable persona fields (§3.2) |
| `prompt_template.j2` | | custom system-prompt template |
| `voice/profile.json` | | voice config (provider-neutral: e.g. `{edge:{voice,rate,pitch}, fish:{reference_id}}`) |
| `voice/reference.wav` | | voice-clone reference audio |
| `embodiment/embodiment.json` | | `kind` (`vrm`\|`glb`\|`fbx`\|`plush`\|`robot`), `model` (in-pack filename or URL), `target_height` (meters), `pose`, `toon`, `idle_clips[]` |
| `embodiment/model.<ext>` | | the 3D model binary |
| `expression.json` | | `intensity` (0–1), `mouth_style` (`mixed`\|`lips`\|`jaw`\|`off`), `pad_baseline` `{p,a,d}` each in [-1,1] |
| `events.json` | | character-specific event/dialogue overrides |
| `studio.json` | | life-runtime persona (traits, daily_goals, energy, relationships, role_label, color, comfort_line, interests, speech_style) |
| `rag/<name>` | | knowledge documents (UTF-8 text) |
| `avatar.png` | | portrait |

### 3.1 `manifest.json`

```json
{
  "version": "2.0",
  "soul_id": "…uuid…",
  "name": "林晚",
  "author": "…", "license": "…",
  "created_at": "2026-08-31T12:00:00+00:00",
  "compat": { "protocol": "0.2", "vrm": "1.0", "soulforge": ">=2026.08" },
  "capabilities": ["voice", "embodiment", "model", "expression", "studio", "knowledge"],
  "files": { "<zip path>": "<sha256 hex>", … },
  "checksum": "<sha256 of the sorted 'path:hash\\n' lines>"
}
```

Readers MUST verify: every path in `files` exists in the ZIP, its SHA-256 matches,
and `checksum` matches the recomputed digest. Any mismatch → reject as tampered.
Files present in the ZIP but absent from `files` MUST be ignored (forward compat),
except `manifest.json` itself.

### 3.2 `character.json` portable fields

`name, archetype, species, backstory, relationship, personality, catchphrases,
suffix, topics, forbidden, response_length, voice_speed, language_mode,
vocalization_palette, age_setting, emotion_config, audio_clips, llm_*,
tts_provider`. Host identifiers (`id`, `brand_id`, timestamps) MUST NOT be
serialized. `personality` SHOULD be the five 0–100 numeric traits
(`extrovert, humor, warmth, curiosity, energy`) — conforming runtimes derive the
PAD emotion baseline from them (`personality_to_baseline`).

## 4. Encryption 加密

`enc="pass"`:

```
key  = PBKDF2-HMAC-SHA256(passphrase, salt, 200_000 iterations, 32 bytes)
blob = 12-byte nonce ‖ AES-256-GCM(key, nonce, zip_bytes)
```

A wrong passphrase MUST surface as a distinct error from a tampered payload.
There is no key escrow: a lost passphrase means a lost soul (by design).

## 5. Versioning 版本

- `manifest.version` is the format version; this document specifies `2.0`.
- v1 (`.soulpack`, brand-key envelope, magic-less) is host-proprietary and NOT part
  of this spec; conforming readers MAY reject it.
- Minor revisions add optional files/keys only. Payload-breaking changes bump the
  magic (`SOUL3\n`).

## 6. Test vectors 测试向量

A minimal conforming soul (plaintext, one character file) can be generated by the
reference implementation:

```python
from soulforge_harness.soul.pack import SoulPackBuilder
blob = SoulPackBuilder().build(character_data={"name": "测试"})
```

Assertions any implementation must pass (see `packages/soulforge-harness/tests`
and `packages/ai-core/tests/test_soul_pack.py`):
round-trip equality of `character.json`; header peek without decryption;
tamper detection on any single-byte change inside a hashed file; wrong-passphrase
error; base64 transport safety.

## 7. Security considerations

- `rag/` documents and `prompt_template.j2` are **untrusted input** to the host's
  LLM: hosts SHOULD apply their own prompt-injection policy when loading a
  third-party soul.
- `embodiment.model` URLs (when not in-pack) MUST be fetched with the host's normal
  content-security policy; the hash in `files` only covers in-pack payloads.
- `soul_id` is an identity claim, not proof of authorship. Publisher signatures are
  planned for the registry layer (out of scope for v2.0).
